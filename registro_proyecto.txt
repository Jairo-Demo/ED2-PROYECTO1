# Registro de Desarrollo - Proyecto: Tres en Raya con Minimax y ML

## Semana 1 - Día 1: Configuración inicial y Arquitectura
- Configuración del repositorio local.
- Creación de la estructura de carpetas bajo el patrón MVC (model, view, controller).

## Semana 1 - Día 2: Lógica del Juego (Modelo)
- Se creó el archivo `model/game_model.py`.
- Se implementó la clase `TresEnRayaModel` definiendo el tablero como una matriz 3x3.
- Se implementaron los métodos solicitados: validación de movimientos válidos, registro de movimientos, comprobación de estado de victoria (filas, columnas, diagonales) y condición de empate.
- Todo el código respeta el estándar PEP 8 e incluye docstrings.
- Se incluyó preventivamente el método `deshacer_movimiento` para el Backtracking futuro.

## Semana 1 - Día 3: Interfaz Gráfica (Vista)
- Se creó el archivo `view/gui_view.py` utilizando la librería Tkinter.
- Se maquetó la clase `TresEnRayaView` dividiendo la ventana en dos marcos (Frames).
- Marco Izquierdo: Matriz de 3x3 con objetos `tk.Button` para el tablero interactivo.
- Marco Derecho: Panel lateral con `tk.LabelFrame` para mostrar el estado del juego (turnos, victorias).
- Se implementó la separación estricta de responsabilidades (MVC): la vista no importa al modelo, simplemente usa una función callback (`set_click_callback`) para enviar eventos de clic al futuro Controlador.

## Semana 1 - Día 4: Coordinación e Interacción (Controlador)
- Se creó el archivo `controller/game_controller.py`.
- Se implementó la clase `GameController` encargada de instanciar la conexión entre el Modelo y la Vista.
- Se desarrolló el método `manejar_clic` para procesar la interacción del usuario con las casillas.
- Se implementó la lógica de flujo de turnos, actualización visual sincrónica del tablero y detección de final de partida (victoria o empate) al ocurrir un evento.
- El código mantiene un enfoque didáctico con comentarios descriptivos paso a paso.

## Semana 1 - Día 5: Integración y Pruebas (Humano vs Humano)
- Se creó el archivo principal `main.py` en la raíz del proyecto.
- Se instanciaron los tres componentes principales (Modelo, Vista, Controlador) logrando la integración final del patrón MVC.
- Se realizaron pruebas exitosas de la modalidad "Humano vs Humano".
- El juego valida correctamente los clics, los turnos, las victorias y los empates.
- Con esto se da por finalizada exitosamente la Semana 1 del proyecto.

## Semana 2 - Día 1: Espacios de Estados y Mecanismo de Backtracking
- Análisis teórico del espacio de estados del Tres en Raya (árbol de juego de orden variable, conceptualmente similar al árbol m-vías).
- Implementación y formalización del mecanismo de Backtracking en `model/game_model.py`.
- Se añadieron los métodos `make_move` y `undo_move` (junto con `get_available_moves` y `check_winner`) para permitir la simulación y reversión de jugadas en el tablero sin alterar partidas en curso.
- Este mecanismo sienta las bases directas para la exploración recursiva del algoritmo Minimax.

## Semana 2 - Día 2: Función de Evaluación Heurística
- Creación del archivo `model/minimax_agent.py` y definición de la clase `MinimaxAgent`.
- Implementación del constructor con variables de control para fichas de jugadores y contador de nodos evaluados (`nodes_evaluated`).
- Implementación de la función heurística `evaluate(board)` para asignar valores numéricos a estados terminales:
  - +10 para victoria de la IA.
  - -10 para victoria humana.
  - 0 para empate o situaciones no terminales.
- El diseño respeta el estándar PEP 8 con tipado y docstrings explicativos.

## Semana 2 - Día 3: Algoritmo Minimax Recursivo y Contador de Nodos
- Implementación del algoritmo `minimax` recursivo en `model/minimax_agent.py` siguiendo las especificaciones del Punto 5 del PDF.
- Integración de los casos base para nodos terminales con penalización/recompensa por profundidad (`score - depth` / `score + depth`).
- Implementación de la alternancia de turnos (MAX para la IA, MIN para el rival humano).
- Aplicación estricta de Backtracking (`make_move` y `undo_move`) en cada paso recursivo.
- Adición de métrica didáctica: contador acumulativo `nodes_evaluated` para registrar la cantidad de nodos explorados por el árbol de búsqueda.
- Implementación del método selector `get_best_move(board)` para retornar la jugada óptima basada en el resultado de Minimax.

## Semana 2 - Día 4: Conexión de Minimax y Selector de Modos
- Actualización de `view/gui_view.py`:
  - Se agregó el selector visual de modos (Humano vs Humano / Humano vs IA Minimax) con `tk.Radiobutton`.
  - Se integró el botón para reiniciar partidas interactivas (`btn_reiniciar`).
- Actualización de `model/game_model.py`:
  - Se implementó el método `reiniciar()` para limpiar la matriz del tablero.
- Actualización de `controller/game_controller.py`:
  - Se integró la instancia de `MinimaxAgent`.
  - Se implementó el flujo automático de respuesta de la IA cuando el modo Minimax está activo: tras la jugada humana, el controlador invoca `get_best_move(board)` y aplica la jugada calculada.
  - Sincronización continua de la vista con los estados de victoria, empate y turnos.

## Semana 2 - Día 5: Visualización de Métricas de Rendimiento en Tiempo Real
- Actualización de `view/gui_view.py`:
  - Se agregó la sección "Métricas de la IA" con etiquetas para `Nodos explorados` y `Tiempo (segundos)`.
  - Se implementó el método `actualizar_metricas(nodos, tiempo_segundos)`.
- Actualización de `controller/game_controller.py`:
  - Se integró el módulo `time` para medir con precisión de microsegundos la latencia de respuesta del algoritmo Minimax.
  - Sincronización en tiempo real entre el cálculo de Minimax, la métrica de nodos evaluados (`nodes_evaluated`) y la interfaz gráfica.
  - Se implementó el reseteo de métricas al reiniciar partidas.
- Con esto concluye exitosamente la Semana 2: Agente de IA Simbólica Minimax 100% operativo con Backtracking y métricas visibles.
